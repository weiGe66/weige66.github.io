Agent 上下文与状态，刷新后怎么接着做

755 字约 3 分钟

2026-11-23

用户说「把上次选的那本书加入待阅读」。助手需要知道「上次选中」是哪条记录，还要确认它现在是否存在。聊天摘要可以保存这次意图。实际选择应记录成稳定的资源 ID，恢复时再从数据源核对。

区分用于解释的话和用于继续做事的数据

内容适合怎么保留恢复时怎么使用
用户目标与限制简洁摘要，保留仍然有效的条件帮助模型理解同一任务
已选择的对象与版本业务 ID 和 revision重新查询并核对
待确认操作操作 ID、待执行参数、当前状态由应用读取，供用户继续确认
最近工具观察保留必要结果、来源 ID 和时间补全回答所需的证据
搜索或工具返回的正文作为有来源的数据放进上下文提取所需信息，权限判断仍由应用处理

会话能保留对话上下文。操作是否已保存、待确认或发生冲突，应以应用的数据为准。上下文裁剪时，可以省掉已经失效的搜索结果，保留目标、经过核验的对象和未完成操作。工具文本里的指令样式文字仍然属于工具数据。 OpenAI · Conversation state

用一个小的检查点恢复选择

下面演示恢复时的版本核对。这里的 load_book 代表已经按当前用户做过访问校验的读取函数，检查点由应用保存。

def restore_selection(checkpoint, load_book):
    record = load_book(checkpoint["book_id"])
    if record is None:
        return {"status": "unavailable"}
    if record["revision"] != checkpoint["revision"]:
        return {"status": "changed", "current": record}
    return {"status": "ready", "book": record}


checkpoint = {"book_id": "book-42", "revision": 3}
previous = {"title": "计算机网络", "revision": 3}
current = {"title": "计算机网络（新版）", "revision": 4}

assert restore_selection(checkpoint, lambda _: previous)["status"] == "ready"
assert restore_selection(checkpoint, lambda _: current)["status"] == "changed"
assert restore_selection(checkpoint, lambda _: None)["status"] == "unavailable"

保存成 checkpoint.py 后可直接用 Python 运行。「对象已变化」时，界面可以显示更新后的候选，并让用户重新选择。旧选择即使仍在聊天摘要里，也不应自动推进状态。

把恢复路径当作一个正常入口

恢复时先加载检查点，再查关联操作状态和资源版本。已经提交的动作可以直接展示结果。等待确认的动作应带着原始参数回来。如果上下文里还写着「准备写入」，而操作表已保存成功，以操作表为准。新会话也应重新检查当前账号的访问权限。

写入侧的处理见 写操作确认与幂等。按来源版本定位原文的另一个例子见 AI 问答引用如何定位原文。
