搜索框先发出 `v` 的请求，再发出 `vue` 的请求。如果后者先返回，随后到达的 `v` 会把结果覆盖回去。还有一种更隐蔽的情况，旧请求先结束，`finally` 把共享的 `loading` 设为 `false`，此时最新请求还在进行。错误提示也有同样的问题。

## 把状态归给当前查询

| 事件 | 页面行为 |
| --- | --- |
| 开始新查询 | 取消旧请求，切换为新查询的加载态 |
| 当前请求成功 | 展示这一查询的结果 |
| 当前请求失败 | 展示这一查询的错误 |
| 旧请求成功或失败 | 丢弃结果，页面继续展示当前状态 |
| 清空输入 | 立即取消旧请求，回到初始状态 |
| 组件销毁 | 取消请求，停止状态写入 |

[防抖](../js工具库/防抖.md)减少发出的请求数，`AbortController` 用于终止支持它的操作，请求身份决定谁能更新页面。即便取消了请求，异步转换、缓存读取和不支持 `signal` 的适配器仍可能返回结果。浏览器中止等待后，服务端也可能已经开始处理请求。取消应与结果校验一起使用。[MDN · AbortController](https://developer.mozilla.org/en-US/docs/Web/API/AbortController)

## 在状态写入处验证请求身份

每次查询创建一个新控制器，用对象身份区分请求。用户从 `vue` 切到 `vue3` 再切回 `vue` 时，两次 `vue` 仍是两个独立请求。示例在加载时清空上一次的结果，让结果和输入始终属于同一次查询。

```js
export function createLatestSearch(load, publish) {
  let active

  function cancel() {
    const previous = active
    active = undefined
    previous?.abort()
  }

  async function search(input) {
    cancel()
    const query = input.trim()
    if (!query) {
      publish({ status: 'idle', items: [] })
      return
    }

    const request = new AbortController()
    active = request
    publish({ status: 'loading', query, items: [] })

    let items
    try {
      items = await load(query, request.signal)
    } catch (error) {
      if (active !== request) return
      active = undefined
      publish({ status: 'error', query, items: [], error })
      return
    }

    if (active !== request) return
    active = undefined
    publish({ status: 'success', query, items })
  }

  return { search, cancel }
}
```

实际接入时，传输层负责检查 HTTP 状态并解析响应。页面负责是否展示错误，以及加载态和旧结果如何切换。以下接口假定成功响应是结果数组。对接实际服务时，还应根据接口契约检查响应结构。[`fetch()` 的响应与取消行为](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch)

```js
import { onScopeDispose, ref, shallowRef, watch } from 'vue'
import { createLatestSearch } from './latest-search.js'

const query = ref('')
const state = shallowRef({ status: 'idle', items: [] })

const { search, cancel } = createLatestSearch(async (value, signal) => {
  const params = new URLSearchParams({ q: value })
  const response = await fetch(`/api/search?${params}`, { signal })
  if (!response.ok) throw new Error(`搜索失败（HTTP ${response.status}）`)
  return response.json()
}, next => {
  state.value = next
})

// 在组件 setup 中使用，让输入变化立即使旧请求失效。
watch(query, search, { flush: 'sync' })
onScopeDispose(cancel)
```

如果在搜索入口加防抖，应该在输入变化时立即撤销上一轮，再延迟发起新请求。否则，旧响应仍能在防抖等待窗口内写入页面。中文输入法可以在组合输入结束后再提交查询，避免为拼音中间态发请求。

这套规则适用于搜索、筛选和详情切换。保存、下单等写操作涉及服务端状态，页面丢弃旧响应以后，仍要按业务契约处理重复提交和幂等。

## 用可控的完成顺序复现

把第一段保存为 `latest-search.mjs`，把下面的脚本保存到同目录，用 `node verify.mjs` 运行。这里让加载函数故意忽略取消信号，以验证晚到的结果仍会被拦截。

```js
import assert from 'node:assert/strict'
import { createLatestSearch } from './latest-search.mjs'

const pending = new Map()
let state
const { search } = createLatestSearch((query, signal) =>
  new Promise((resolve, reject) => pending.set(query, { resolve, reject, signal })),
next => { state = next })

const old = search('v')
const latest = search('vue')
assert.equal(pending.get('v').signal.aborted, true)

pending.get('vue').resolve(['Vue'])
await latest
pending.get('v').resolve(['Vanilla'])
await old
assert.deepEqual(state, { status: 'success', query: 'vue', items: ['Vue'] })

const previous = search('vu')
const current = search('vue3')
pending.get('vu').reject(new Error('旧请求失败'))
await previous
assert.equal(state.status, 'loading')
assert.equal(state.query, 'vue3')

await search('')
pending.get('vue3').resolve(['Vue 3'])
await current
assert.deepEqual(state, { status: 'idle', items: [] })
```

做页面回归时，再覆盖当前请求失败、切换路由后返回、连续输入同名查询这三种情况。断言里同时看结果、加载态和错误提示，才容易发现只修了一半的竞态。
