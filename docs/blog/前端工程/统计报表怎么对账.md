学习工作台的统计页有专注时长、任务完成率、评分分布和打卡热力图。接图表之前先要回答两件事。用户点一个数字，能看到构成它的事实吗？同一时间打开首页和报表，日期口径一致吗？

## 先写清楚每个数字怎么算

| 指标 | 以什么时间归属 | 前端怎么对账 |
| --- | --- | --- |
| 专注时长 | 已完成会话按有效时段拆到业务日 | 明细展示当天分摊和实际结束时间 |
| 已完成任务数 | 当前已完成、未删除任务的完成日期 | 明细按完成日期查 |
| 到期任务完成率 | 所选日期范围内的截止日期 | 同一批到期任务，全部是分母，当前已完成的是分子 |
| 复习评分分布 | 成功提交的评分事实发生时间 | 同一操作重放只计一次，重新练习产生的新评分计一次 |

假设 A 周一到期、周二完成，B 周一到期、仍未完成。周一的到期完成率是 `1/2`，周一的已完成任务数是 `0`。由于项目用当前任务状态计算历史到期完成率，周二完成以后，回看周一会看到分子增长。如果产品要求看到「截至周一结束时的完成率」，就需要历史状态或快照。

分母为空时返回 `null`，界面显示「无到期任务」。有一项到期且尚未完成时，数据是 `0/1`。只保留四舍五入后的百分比，会让这两种情况难以区分。周汇总同样应先加总分子与分母，再计算比例。

## 日期与时刻分开传

日期选择器送出 `YYYY-MM-DD`。它表示用户选的业务日，前端可以原样传给接口。把它转成 JS `Date` 再显示成设备本地日期，可能跨到前一天。后端用业务时区解释日历日期，查询时间戳时采用 `[开始日零点, 结束日的下一天零点)`。同一条边界上的事实只归属一个区间。[MDN · 日期输入值](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/input/date) · [MDN · Date.parse](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/parse)

下面的样例使用 Python 3.9+。分别计算两个本地零点，再用 UTC 时刻计算持续时间，覆盖跨午夜以及夏令时切换。

```python
from datetime import date, datetime, time, timedelta, timezone
from zoneinfo import ZoneInfo


def utc_day_bounds(day, zone):
    start = datetime.combine(day, time.min, zone)
    end = datetime.combine(day + timedelta(days=1), time.min, zone)
    return start.astimezone(timezone.utc), end.astimezone(timezone.utc)


def overlap_minutes(start, end, bounds):
    left = max(start, bounds[0])
    right = min(end, bounds[1])
    return max(0, (right - left).total_seconds()) / 60


shanghai = ZoneInfo("Asia/Shanghai")
start = datetime.fromisoformat("2026-10-14T15:50:00+00:00")
end = datetime.fromisoformat("2026-10-14T16:30:00+00:00")
assert overlap_minutes(start, end, utc_day_bounds(date(2026, 10, 14), shanghai)) == 10
assert overlap_minutes(start, end, utc_day_bounds(date(2026, 10, 15), shanghai)) == 30

start, end = utc_day_bounds(date(2026, 3, 8), ZoneInfo("America/Los_Angeles"))
assert (end - start).total_seconds() == 23 * 3600
```

时区标识应由服务端统一解释。报表返回时区、统计日期和取数时点，页面据此展示。同一时点尤其重要，比如请求正好跨午夜，图表和卡片应使用同一业务日。[Python · zoneinfo](https://docs.python.org/3/library/zoneinfo.html)

## 让聚合结果可以回到原始事实

该项目把每日统计当作可重建的投影。首次回归中，有条旧用例直接给投影写了 120 秒，却没有对应的完成会话。新查询从事实重建，把它修正为 0。修复测试时改用真实的完成事实构造数据，保留了回归检查，也避免测试夹具替产品定义统计口径。

浏览器验收使用合成数据，报表显示到期任务完成率 `20/30`。明细能分别查到 30 条到期任务和其中 20 条已完成任务。点击专注折线上的日期，也能看到该日分摊和会话实际结束时间。图表之外同时提供按钮和表格入口，键盘操作也能到达明细。

离开这套产品后，具体口径可以换。可迁移的做法是为指标写出归日字段、纳入条件和可核对的明细。聚合若可重建，用相同事实重跑两次应得到同一个结果，避免补数任务把数据越加越大。

日期筛选器的窄屏与键盘检查见 [原生表单控件的样式回归](./原生表单控件的样式回归.md)。
