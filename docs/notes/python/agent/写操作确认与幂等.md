阅读清单助手准备把《计算机网络》加入待阅读。界面先显示清单与书名，请用户确认。随后服务端写入成功，浏览器却没收到响应。此时重试的目标是确定这一笔操作的结果。再次向模型请求执行，可能生成新的操作 ID。

## 让确认绑定到一份待执行记录

| 阶段 | 应用应持有什么 |
| --- | --- |
| 生成提案 | 操作 ID、资源 ID、目标清单和参数快照 |
| 用户确认 | 来自当前用户的确认，绑定同一个操作 ID 和参数 |
| 执行 | 验证当前权限和操作状态，按原参数写入 |
| 重开或超时 | 查询或重放原操作；已有结果时返回同一条记录 |

确认界面展示用户真正要执行的动作。对象、目标或主要参数变化时，应生成新提案并重新确认。确认状态由受信任的应用入口写入，模型可以提出待办，执行端仍需要核对这笔操作的确认状态。 [OpenAI Agents SDK · Human in the loop](https://openai.github.io/openai-agents-python/human_in_the_loop/)

## 用本地事务验证同一操作只插入一条

这个示例只写入内存 SQLite。待处理记录保存了将要使用的书名。模拟确认以后，服务端按操作 ID 读取原提案。清单以操作 ID 为唯一键，重复请求返回已存在的条目。

```python
from contextlib import closing
import sqlite3


def add_approved_book(db, operation_id):
    with db:
        db.execute("BEGIN IMMEDIATE")
        intent = db.execute(
            "SELECT title, approved FROM actions WHERE id = ?", (operation_id,)
        ).fetchone()
        if intent is None or not intent[1]:
            return {"status": "needs_approval"}

        db.execute(
            "INSERT INTO reading_list (action_id, title) VALUES (?, ?) "
            "ON CONFLICT(action_id) DO NOTHING",
            (operation_id, intent[0]),
        )
        (entry_id,) = db.execute(
            "SELECT id FROM reading_list WHERE action_id = ?", (operation_id,)
        ).fetchone()
        return {"status": "saved", "entry_id": entry_id}


with closing(sqlite3.connect(":memory:")) as db:
    db.executescript("""
        CREATE TABLE actions (
            id TEXT PRIMARY KEY NOT NULL,
            title TEXT NOT NULL,
            approved INTEGER NOT NULL CHECK (approved IN (0, 1))
        );
        CREATE TABLE reading_list (
            id INTEGER PRIMARY KEY,
            action_id TEXT NOT NULL UNIQUE,
            title TEXT NOT NULL
        );
        INSERT INTO actions VALUES ('op-1', '计算机网络', 0);
    """)
    assert add_approved_book(db, "op-1") == {"status": "needs_approval"}
    assert db.execute("SELECT count(*) FROM reading_list").fetchone() == (0,)

    # 模拟用户在确认界面同意这条提案。
    with db:
        db.execute("UPDATE actions SET approved = 1 WHERE id = ?", ("op-1",))

    first_result = add_approved_book(db, "op-1")
    second_result = add_approved_book(db, "op-1")
    assert first_result == second_result == {"status": "saved", "entry_id": 1}
    assert db.execute("SELECT count(*) FROM reading_list").fetchone() == (1,)
```

保存成 `approved_write.py` 后可直接运行。确认检查与写入都在同一个事务中，离开上下文成功提交后，调用方才会得到返回值。实际服务还需按用户定位提案，并校验目标资源和有效期。 [Python · sqlite3 的连接上下文与事务](https://docs.python.org/3/library/sqlite3.html#how-to-use-the-connection-context-manager)

## 外部写入的结果要另外核对

如果工具操作第三方 API，本地表和第三方系统之间有独立提交边界。可以保存本地操作 ID，传给支持幂等键的第三方，并在超时后查询状态。没有状态查询或幂等能力时，应用应标记「结果待核对」，避免下一轮误把超时当成失败并重新执行。
