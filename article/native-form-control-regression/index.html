统一表单控件的样式，如何保留原生交互

1055 字约 4 分钟

前端工程css可访问性

2026-11-23

学习工作台做全站样式统一时，下拉框和日期框的高度在不同页面出现了 36、38、40、42 和 44 px。修改圆角变量后，还有部分页面没跟上。将这些控件与各页面的相关样式放进独立复现页，才看清差异来自哪里。

先量框体，再量内容区

看到的问题检查方式修复位置
控件看起来比相邻按钮高比较 getBoundingClientRect().height，跟踪最终 padding、line-height 和 min-height共享控件样式统一盒模型和尺寸，页面只给布局宽度
文本压住下拉箭头检查内边距与图标的实际边界，换成长选项再测共享控件保留尾部空间，装饰图标不接管点击
日期顶出工具栏用窄视口和填好的日期核对控件与父容器宽度日期区域有足够宽度，空间不足时让工具栏换行
一些圆角没改检查实际计算样式，再查旧变量和硬编码同一语义的外框统一用 token，接缝和圆形标记单独处理

先只改外框，再做第二轮图标检查。项目当时统一了桌面 36 px、窄屏 44 px 的框体，仍有 13 项图标留白不达预期。把图标尺寸、尾部留白和对齐也纳入共享规则后，几何验证才全部通过。这些尺寸是项目的设计值，适配其他组件库时应以文字缩放和目标设备实测为准。

让样式层只负责样式

简单单选继续用原生 select。可以改变外观并绘制装饰箭头，仍由原元素负责选值、提交和键盘响应。日期继续用 input[type=date]，保留浏览器的日期分段编辑和值格式。日期弹出面板由平台绘制，可以统一输入框外壳，同时允许不同浏览器的选择器有所差异。MDN · appearance · MDN · 日期输入

这个示例只演示单选框。箭头不拦截点击，强制色彩模式恢复系统箭头。把以下两段放进同一 HTML 页面即可检查样式与交互。

<label for="status">任务状态</label>
<span class="select-shell">
  <select id="status" name="status">
    <option value="all">全部</option>
    <option value="open">待完成</option>
    <option value="done">已完成</option>
  </select>
  <span class="select-arrow" aria-hidden="true"></span>
</span>
.select-shell {
  position: relative;
  display: inline-grid;
  min-inline-size: min(10rem, 100%);
  max-inline-size: 100%;
}
.select-shell select {
  appearance: none;
  box-sizing: border-box;
  inline-size: 100%;
  min-inline-size: 0;
  min-block-size: 2.25rem;
  padding-block: 0.25rem;
  padding-inline: 0.75rem 2.5rem;
  border: 1px solid currentColor;
  border-radius: 0.3125rem;
  background: Canvas;
  color: CanvasText;
  font: inherit;
}
.select-shell select:focus-visible {
  outline: 2px solid Highlight;
  outline-offset: 2px;
}
.select-arrow {
  position: absolute;
  inset-inline-end: 0.875rem;
  inset-block-start: 50%;
  inline-size: 0.5rem;
  block-size: 0.5rem;
  border: solid CanvasText;
  border-width: 0 2px 2px 0;
  transform: translateY(-75%) rotate(45deg);
  pointer-events: none;
}
@media (max-width: 37.5rem) {
  .select-shell select { min-block-size: 2.75rem; }
}
@media (forced-colors: active) {
  .select-shell select { appearance: auto; }
  .select-arrow { display: none; }
}

强制色彩模式会改变部分作者提供的颜色。留着系统颜色和原生箭头，可以少维护一套图标对比度规则，同时仍要测试焦点是否可见。MDN · forced-colors

验收要把外观和交互放在一起

项目用 Chromium 对 13 个字段跑了亮暗两套主题和 360、768、1440 px 三种宽度，共 78 组几何检查。另一组验证用键盘选值、编辑年份、检查 Tab 焦点，以及确认只读和禁用状态。几何检查回答「放得下、对得齐」，键盘检查回答「还能正常操作」。

迁移到其他项目时，移除旧的页面覆盖后再跑同一组检查。把每个控件的长值、空值和错误态也塞进窄屏，确认不会靠全页面横向滚动解决。平台原生日历、系统高对比度和移动端输入还值得在目标设备上单独验收，原项目的 Chromium 记录只覆盖了当时列出的路径。
